# Four-rank FSDP implementation — 16 November 2026

## Scope and status

Added `exact_pass_fsdp.py` with full-shard Llama wrapping, per-decoder nonreentrant activation checkpointing, optimizer construction after wrapping, synchronized accumulation, FSDP global clipping and final checkpoint export. There is no executable training CLI or approval grant. `prepare_fsdp_candidate.py` performs CPU-only binding and optional installed-API inspection. The legacy DDP path and historical receipts remain intact.

The proposed strategy uses four GPUs on one node, provisionally 80 GB each. GPU fit and interconnect are not verified. Approximate persistent FP32 parameters, gradients and Adam state are 28 GB per rank, excluding activations, transient unsharded layers, communication and allocator buffers. Loading and final checkpoint gathering also require host RAM. This is a planning estimate, not a measured allocation.

## Specific choices

- FULL_SHARD, use_orig_params=True, no CPU offload, bounded all-gathers, no forward/backward prefetch.
- FP32 persistent shards, BF16 forward parameters/buffers, FP32 reduction, no gradient scaler. Causal loss is computed in at least FP32.
- Same optimizer/LR proposal as the prior DDP draft. Capture decay classification before wrapping because original parameters become one-dimensional or empty shard views. Construct AdamW after wrapping and verify original parameter identities.
- Four ranks × four microsteps retains the prior global maximum of 16 real examples per update. Two exact passes produce 238 updates, not the 120 updates from the earlier four-rank/eight-microstep diagnostic.
- Every microstep synchronizes gradients; no FSDP no_sync and no CPU-offloaded accumulation. Each example mean is scaled by 4 / actual valid examples in that window, with no additional accumulation division.
- Partial windows use an existing same-window record for an empty rank's forward. Its loss is multiplied by zero, so it is not an extra supervised presentation. This makes all ranks traverse the model and collective sequence. Four such forwards occur per role across two passes. They consume compute/RNG but contribute zero loss; real Llama behavior remains untested.
- All ranks invoke FSDP's global gradient clipping. Local generic clipping would be incorrect for sharded gradients. Empty local parameter shards can legitimately have no gradient.
- All ranks participate in final full-state-dict collection, offloaded to CPU with rank-zero-only materialization. Only rank zero writes weights/config, with a completion marker last. Tokenizer identity remains in the launch binding. Optimizer/resume checkpoints are unsupported. Partially written outputs must not be used or resumed.

Tests cover exact membership, zero-weight carrier behavior, prohibition of no_sync, pre-wrap decay classification and failed grants before model construction. These tests use arithmetic/spies; they do not execute FSDP or AdamW.

Corpus and annotation hashes and paired record order were checked. Existing private markers, mapping, corpus and native evidence are unchanged. The shared BoundWindows constructor now accepts an optional accumulation argument (default remains eight); its new binding includes that value. Historical source receipts are preserved, not rewritten.

## Remaining launch requirements

The CPU-only environment cannot establish NCCL, BF16, full-model activation checkpointing, optimizer state memory, or checkpoint round-trip correctness. The next runtime requirement is a separately scoped GPU-enabled environment/resource and mechanical validation plan, followed by recipe and training approval. No existing CPU receipt grants those permissions. The future entry must recompute file/corpus/code/resource/output bindings before calling the guarded builder; it must reserve output directories and supervise distributed failures. No current command launches this path.

Preserve the 132-response transfer allocation, disabled optional 32-response diagnostic, development-source interpretation and unmatched historical semantic controls.

API documentation is not runtime verification.

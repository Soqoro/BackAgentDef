## Delivered behavior and explicit limitations

- `seek/discovery_phase/methods.py`: query-only incident selection with exact
  snapshot/prompt/token/group binding; public projection; seeded fixed schedule;
  authored/versioned/parented hypotheses; typed compiler errors; bounded sequential
  Qwen/victim phases; one primary candidate or abstention. Unsupported operator
  families are returned unchanged to the author, not silently converted.
- `common.py`: existing authoritative Registry/Journal reuse, global allocation,
  input and consumed-token exposure checks, deterministic cache accounting,
  model/runtime identity binding, raw-journal reconstruction and source checks.
- `panels.py`: candidate-specific 12-pair held-out finite evaluation, 96-response
  adapted observation bridge plus 24 neutral controls and six anchors, exact-input
  inspection with unknown fields retained, and optional 108-response query table.
- `campaign.py`: per-study immutable simulated allocations/results, deterministic
  resume, adaptive/fixed schedules, scales 1/2/4, real 16-block checks, error/coverage
  events at study level, Monte Carlo intervals, costs and separate assumption stress.
- `seek_discovery.py` / `.sh`: CPU preparation/review/preflight, serial cluster
  workers, engineering pilot gate, evaluator freeze and independent raw recomputation.

The discovery cap is 16 logical responses, but the four-role/six-round protocol
currently spends at most ten before a final discussion round. Both probing methods
have this same ceiling; do not advertise this as a completed 16-response budget
comparison. No physical cache is shared between discovery methods. The evaluator
can share exact prompts across frozen candidates while charging all logical access.

The observation families are source-derived adaptations of existing label and
factorial text formats. Their content differs (generic everyday labels versus
explicit footwear facts), so this is a **bundle diagnostic**, not an isolated
layout intervention or historical replay. Exact old cluster prompt records are
still needed for the separate input audit. No expanded 324-response query table
or new anytime campaign is automatically prepared.

The new registry event/schema is an extension. Legacy historical audit readers
may list these new allocations as missing old-format artifacts; use the new
`summarize` command for their evidence. See AUDIT_ADDENDUM.md for migration notes.
